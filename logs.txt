current pipeline (4:30PM)
1. Indexing (indexer.py, run once in build_index())
Tokenization T: text → [token]
Regex [a-z0-9]+ on lowercased text — alphanumeric maximal runs, no punctuation survives, no handling of hyphenated compounds, numbers, or units as distinct entity types.
Stopword removal against a fixed standard English list (~150 words), applied before stemming.
Stemming: Porter stemmer, LRU-cached per unique surface form.
Index structure: classic inverted index.
postings: term → {doc_id → tf} (term frequency, no positions)
doc_len: doc_id → token count
N, avg_doc_len: corpus-level scalars
No positional information, no field structure (single flat text per doc, no title/body distinction available in this corpus per your earlier note), no document-level metadata beyond length.
Persistence: term-sorted, delta-varint-encoded postings in one contiguous blob + offset table, doc lengths as a flat varint array, all gzip-compressed (level 9). ~18.7MB for the current corpus.
2. First-pass retrieval (bm25.py)
Standard Okapi BM25, k1=1.6, b=0.5 (tuned), Robertson-Sparck-Jones +1-smoothed IDF. Query terms are unweighted set (set(tokens) — note: query term frequency is discarded here, a duplicate query term contributes no extra weight in this path). Single postings traversal per query term, heapq.nsmallest for top-k.
3. Query expansion (custom_scorer.py's PRF)
RM3-lite, three stages:
First-pass BM25 → top PRF_TOP_DOCS=10 docs.
Expansion term extraction: for each of those 10 docs, weight every one of its terms by (tf/doclen) × IDF(term); sum across the 10 docs; keep top PRF_TOP_TERMS=10 terms by this score, dropping any term with corpus-wide df/N > PRF_MAX_DF_RATIO=0.15; normalize kept weights to sum to 1.
Query model interpolation: original query terms get uniform weight 1/|Q| each; combined weight per term = α·orig + (1-α)·expansion, α=0.5; second BM25 pass (_weighted_bm25_scores, a from-scratch weighted generalization of the BM25 formula) over this combined term set.
4. Fusion (custom_scorer.py's score())
Reciprocal Rank Fusion over two ranked lists (original BM25, PRF-rescored), RRF_K=60:
fused(d) = Σ_lists weight_list / (RRF_K + rank_in_list(d))
Currently: BM25_WEIGHT=0.65 (dead weight — this is only ever used if VSM fusion is on, but wait — actually BM25's own list is always fused in with BM25_WEIGHT, let me check... yes, the base BM25 ranking is always added to rrf using BM25_WEIGHT/(RRF_K+rank), and PRF's list is added using PRF_WEIGHT/(RRF_K+rank). So BM25_WEIGHT=0.65 and PRF_WEIGHT=1.0 (just frozen) — these are asymmetric and this asymmetry was never itself swept as a pair, only PRF_WEIGHT alone against a fixed BM25_WEIGHT=0.65.)
VSM fusion: off (measured negative ROI: no quality gain, ~2× latency).
Coverage bonus: off (measured negative ROI: double-counts PRF's own effect).
5. Output
heapq.nsmallest(k, ...) on (-score, doc_id).
6. Robustness
retrieve() wraps custom_scorer.score() in try/except, falling back to plain BM25 on any exception.
